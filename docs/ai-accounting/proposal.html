How it works

Three things that keep this reliable

The accounting process stays in control. The AI does the heavy lifting inside each step. It is not the source of truth.

⚙️

Code handles anything with a definite answer

Do debits equal credits? Is the client VAT registered? Does this account already exist? Software checks these every time. They are never sent to an AI.

🧠

AI handles genuine judgement calls only

Which account does this Stripe payment belong to? Is this a capital or revenue expense? The AI reasons using MA's own rules, last year's file, and each client's historical decisions, not generic internet knowledge.

👤

A qualified accountant approves everything that matters

Bank rec and trial balance are finished before sign-off. Uncertain lines wait in a table with a real question. Nothing goes to HMRC or Companies House without a person.

Phase 1 · the hard problem

How we categorise each bank line, and how we keep it honest

This is the core of Phase 1. The AI does not guess a category and hope. Every line goes through a fixed order. Earlier steps win. If it is not sure, it asks you a real question. We score this every week against jobs you have already completed.

1

Known mapping first

Has this supplier or description already been coded for this client? If yes, use that. No AI involved. Amazon for this client is Stationery because you said so last year.

2

Firm rules second

If there is no client mapping, check MA's approved rules. VAT codes, P&L vs balance sheet, "create a new account when...". Code answers these. The model does not.

3

AI only when those miss

Then, and only then, the AI proposes an account and VAT code. It sees the client's trade, last year's file, and HMRC's allowable expense list. Most lines sit on that list. The hard call is personal vs business, not "is this stationery."

4

Ask. Never silent-guess

Low confidence, or a line that does not fit the business (Emirates on a car-wash client), goes to you with a specific question. Your answer can become a standing rule for that client. Guessing is not allowed.

How we know it is actually getting it right

Every week we run this against a real MA job you already finished, without showing the AI your answer. Each line is scored. Target is 90%+. The rest must be flagged with a question, not posted wrong. After that, software still checks trial balance and bank rec before sign-off.

The build plan

Three phases · each one builds on the last

Bank to trial balance first, scored every week. Then documents. Then the rest of the pipeline. No six-week silence, no one-shot demo.

Bank statements to trial balance · learning phase

Sandbox · weekly scorecards

Bank in, trial balance out. No invoices yet. Categorisation is the work. Weekly scorecards on real MA jobs. Target 90%+. This is a learning phase, not a stop/go gate.

What gets built
  • OneDrive drop zone (copy in, server picks up)
  • Bank CSV / Excel in, categorisation chain, exception table
  • Trial balance + bank rec as hard checks
  • Weekly scorecard on a real MA job
  • AI Accountant inside the live MA dashboard (chat, status, download)
What you walk away with
  • A weekly scorecard, not one demo at the end
  • 90%+ target before you rely on the output
  • TB balanced / bank rec agreed (hard checks)
  • Questions, not silent guesses
  • Corrections proposed as standing client rules

2

Documents, invoices and a system that learns

Substantially more powerful

Invoices and documents sit behind each bank line. FreeAgent can feed invoices where the client already uses it (read-only API). Corrections become standing client rules once a senior approves them. Nylon is optional later, only for complex edge cases, not required.

What gets built
  • PDF and image ingestion, match invoice to bank line
  • Net and VAT checked against the actual invoice
  • Output in MA's real Excel template
  • Client memory: recurring suppliers, corrections as standing rules
  • FreeAgent as a read source where the client already uses it
What you walk away with
  • Per transaction: account, VAT, invoice, confidence
  • Output matches MA's Excel template
  • Missing documents surface before anyone asks
  • Gets better with every job, only after a senior approves the rule

3

Full accounts pipeline · source to client-ready output

Full pipeline

Year-end, VAT, and personal tax, with a human on final sign-off. MTD is in scope. For many clients that work already happens inside FreeAgent, and FreeAgent's API is read-only, so we will test the route that actually files (including operating the software directly) rather than assuming an API can submit.

What gets built
  • Year-end, VAT, and personal tax
  • Client queries, summaries, deadline alerts
  • Per-client job history (the later idea, not day one)
  • MTD filing path, tested rather than assumed
What you walk away with
  • Full job from source to signed-off accounts
  • Same process for every member of staff
  • Seniors on judgement, not routine processing
The win at this stage

Routine work is automated. Seniors spend time where it actually matters. The system sits in how MA operates, not as a side tool.

Common questions

What you're probably wondering

What if the AI gets it wrong?

Uncertain lines go to the exception table with a real question, not a silent guess. Trial balance and bank rec are checked by software before you are asked to sign off. Nothing goes to HMRC or Companies House without a qualified accountant.

Does it replace the accountants?

No. It does the routine bookkeeping pass so your team spends time on judgement, queries, and sign-off. Headcount is not the goal. Submissions stay human-approved.

Is client data secure?

See Data protection. Ideas to agree, not a locked spec. Direction: MA's database, optional Data Centre, business APIs with zero retention, MFA, and a choice on how long raw files are kept.

Is this only bookkeeping, or a general MA assistant?

Phase 1 is accounting jobs only: bank to trial balance. A wider MA chatbot is a later choice, not mixed into the first build.

Can it do VAT, personal tax, and MTD?

Not in Phase 1. Phase 1 is bank to trial balance. Documents and FreeAgent (read) in Phase 2. VAT, personal tax, and MTD in Phase 3. We will test how MTD actually files, because FreeAgent's API cannot submit.

What if the person who built this is unavailable?

Three backups, written into the contract: MA gets the code and hosting; a knowledge-transfer session if Faraz hands over to Qasim; a named developer as ongoing contact, not only one person.
